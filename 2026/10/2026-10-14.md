#### HelloClaw web session replay bug
- **Repo:** `nimblee` (helloclaw-web / Hermes)
- **Question:** Why do helloclaw-web conversations reload the full uncompressed history on every turn after Hermes compresses a long chat once? This had to be fixed before the [HelloClaw profile split](https://app.notion.com/p/nimblytechnologies/HelloClaw-split-Hermes-into-eng-CS-and-sales-profiles-3f4c00148769810ba9cac7327f3b6c38) (eng / CS / sales) so the bug isn't copied into each profile.
- **Outcome:**
  - **Root cause:** Hermes API-server loads history by the raw session id and returns the new head as `session_id` on `run.completed`. helloclaw-web never saves that new head, so every later turn replays from the old uncompressed root.
  - **Fix:** Drafted in a scratchpad (not committed to any repo):
    - added a `hermes_session` column in `lib/db.ts`
    - updated the chat, messages and conversation routes to send to the current head and follow the new one
    - added backfill and verify scripts
  - **Write-up and tracking:** Wrote it up in `docs/analysis/helloclaw-web-session-replay-2026-10-14.md` and created a Fizzy card on the HelloClaw board, assigned to me.
  - **Split plan:** Also worked through step 2 of the split plan: put the shared skills (`nimbly-playbook`, `hubspot-crm`, `customer-contracts`) in one git-tracked place instead of copying them into each profile.
- **Time:** 12:42–14:42
