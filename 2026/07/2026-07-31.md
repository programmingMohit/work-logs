#### Guard unsynced work before account switch (OF-1591)
- **Repo:** `Nimbly-Technologies/audit-lite` · branch: `feat/of-1591-unsynced-work-switch-guard`
- **What was done:** Closed the P0 where logging in as a different user on a shared device silently called `clearAllUserData()` from `handleUserSwitch`, destroying the previous auditor's queued reports, open questionnaire draft, and in-flight photo uploads with no prompt. Added a single `unsynced-work-service` predicate reading three independent sources (ready-to-upload reports, active questionnaire session, latest `upload_jobs` row per `localUri`), deduped so retries aren't double-counted, with `deferred_client_blocked` counted as unsettled. Each read is isolated and any failure sets `readFailed`, which is treated as "warn" — a needless tap beats a lost audit. The confirmation is injected as an optional `confirmSwitch` callback, so omitting it leaves existing behaviour byte-for-byte identical; refusal throws `UserSwitchDeclinedError` (deliberately excluded from `isAuthError`) before both `clearAllUserData()` and `setLastLoggedInUserId`. Deviated from the card on purpose: logout preserves MMKV and destroys nothing, so it only gets a softer warning line — the blocking guard went where the destruction actually happens. 45/45 affected unit tests pass, 24 integration suites pass, `tsc` clean in touched files. Docs at `docs/technical/unsynced-work-guard.md`.
