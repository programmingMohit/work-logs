#### Org-gated Sentry ingest for questionnaire flow anchors
- **Repo:** `audit-lite` · branch: `feat/org-gated-flow-event-capture`
- **What was done:** `captureFlowEvent` was billing the Sentry errors quota via `captureMessage`, with the three questionnaire `*_attempted` anchors accounting for ~98% of volume (99,156 of 100,609 events over 17 days) despite never signalling a problem on their own. Gated them behind a 2% baseline sample rate that rises to 100% for orgs enrolled in the `flow-event-full-capture` PostHog flag (targeted by the `organizationID` person property). Failure anchors stay ungated since they're low-volume and are what alerts fire on. The flag is read at PostHog flag-load rather than per event — a hot-path `isFeatureEnabled()` would emit `$feature_flag_called` on every submission and merely shift the overage to PostHog — and enrollment is cached in MMKV so it survives cold start and holds offline. Opened, self-assigned, commented on and merged same day.

#### Unstick issue comment sheets on failed submit
- **Repo:** `audit-lite` · branch: `fix/issue-comment-sheet-stuck-submitting`
- **What was done:** The comment/resolve/block sheets ran `setIsLoading(true)` → bare `await` → cleanup with no error path, so a rejected mutation left the button locked on "Submitting" and the sheet impossible to close — often after the comment had actually landed server-side, since `issue-repository` throws on any apisauce `problem` including client-side `TIMEOUT_ERROR`/`CONNECTION_ERROR`. Wrapped the four handlers in try/catch/finally, kept `resetData()` inside the try so failed submits preserve draft text and attachments, added per-sheet error logging and toasts, and restored `issueDetailsAtom` in the catch so the screen stops claiming a status that was never written. Separately replaced the hardcoded `pb="$10"` (44px) reservation for the ~66dp resolve bar with an `onLayout`-measured height, so the comment input's border is no longer clipped and the gap collapses to 0 when the button is hidden. Added two regression cases, which required making that test file's jotai mock atom-aware — it had returned one shared value for every atom, leaving the submit button permanently disabled so no test had ever exercised submit.

`★ Insight ─────────────────────────────────────`
- The #1835 design turns on a detail that's easy to miss: PostHog's `sendFeatureFlagEvent` means *reading* a flag is itself billable telemetry. Sampling decisions that need to be cheap belong at flag-load time, not on the hot path — otherwise you relocate the cost instead of removing it.
- The two-opposed-tests pattern in #1830 (characterization + `it.fails`) exists because `it.fails` is a weak assertion: it passes whenever the body throws, harness rot included. Pairing it with a test that passes *now* and breaks on the fix gives you a two-bit signal instead of one.
