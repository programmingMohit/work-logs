### Tasks & Changes

#### Check-in offscreen probe false positives
- **Repo:** `audit-lite` · branch: `fix/checkin-probe-usable-bottom`
- **What was done:** The offscreen probe subtracted `insets.bottom` from `windowHeight`, but on three-button-nav Android the window already ends above the nav bar — removing the strip twice put the fold ~48dp inside the sheet footer. Fixed to subtract only the overlap the window still spans, so gesture-nav devices (`screen.height === window.height`) keep the full subtraction and remain detectable. Also emits `usable_bottom_dp` and derives `overflow_dp` from the same value, so a future formula bug surfaces in the data rather than hiding in it. First release measured 21,580 `schedule.checkin_button_offscreen` against a 2% baseline of 1,042 — all false positives; the original OPPO A60 report still has zero credible occurrences.
- **Commits:**
  - `863cc13` — fix(schedule): stop the check-in probe counting the nav bar twice

#### Report submission screen
- **Repo:** `audit-lite` · branch: `feat/report-submission-screen`
- **What was done:** Built the surface auditors land on after Complete and where failed submissions are explained. It reads the report's newest outbox op and its upload rows and drives nothing, so leaving and returning finds the same state. Failure *kind* is now projected alongside status (a missing file and an exhausted retry budget want opposite things from the auditor), with readers going through the queue's own `isRedrivableUploadJob` rather than comparing kinds. Resubmission files a genuinely new op — new id, new idempotency key, higher seq, via `commitReportForSubmission` — never a reset of the dead row, since that would replay a possibly-stale snapshot under a key the server has already seen; the no-reset rule is asserted structurally by a suite that reads every source file the screen is made of and refuses any write against `report_sync_ops`. Complete now resets rather than replaces the stack, closing a hardware-back path that left a live edit surface for a locked report one press away. Schedule rows lead here from both queued and failed states, making the screen re-enterable rather than one-shot.
